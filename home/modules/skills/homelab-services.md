# Домашние сервисы: Traefik и Homepage

## Контекст

Сначала определи ОС, в которой запущен агент, и выбери каталог данных:

- **macOS (Darwin):** `/Volumes/appdata`.
- **Linux:** путь пока не задан — его нужно будет добавить в этот скил после уточнения у пользователя. Не используй автоматически macOS-путь и не угадывай точку монтирования. Перед работой с конфигурациями уточни существующий путь и проверь доступность каталога; если данные ещё не подключены, согласуй их подключение с пользователем. Создание пустого каталога не заменяет подключение данных.

Прочитай `AGENTS.md` в выбранном каталоге и относящиеся к задаче локальные инструкции. Если каталог недоступен, установи актуальный путь у пользователя. Все пути ниже указаны относительно выбранного каталога данных. Это рабочие данные приложений, а не исходный код Nix-развёртывания; сохраняй регистр путей и соседние настройки.

- `traefik/traefik.yml` — entry points и providers.
- `traefik/dynamic.yml` — файловые маршруты `http.routers` и backend-адреса `http.services`.
- `homepage/services.yaml` — карточки и виджеты; содержит секреты.
- `homepage/settings.yaml` — раскладка групп.
- `homepage/docker.yaml` — подключение к Docker.

Сверяй эти сведения с текущими файлами. Читай только относящиеся к задаче фрагменты; не выводи ключи и пароли, не обходи базы и журналы без необходимости.

## Порядок работы

1. Установи имя сервиса, hostname, схему и внутренний адрес с портом, группу и иконку Homepage, необходимость виджета. Используй запрос и существующую конфигурацию; недостающие адреса, порты и учётные данные уточни. Не подставляй стандартный порт без подтверждения. Существующая сеть и домены — ориентир, а не источник адреса нового сервиса.
2. Проверь текущие маршруты и карточки на дубликаты. Учти Docker provider: отсутствие маршрута в `dynamic.yml` не означает, что его нет. При наличии доступа проверь относящиеся к сервису Docker labels; если источника нет, обозначь этот пробел.
3. Для файлового provider добавь или измени router с согласованными `rule`, `entryPoints`, `service`, а также service с `loadBalancer.servers[].url`. Повтори локальный стиль. Выбирай HTTP/HTTPS и TLS по заданию и текущей конфигурации; наличие `websecure` само по себе не подтверждает настройку сертификатов.
4. Добавь или обнови карточку в нужной группе `homepage/services.yaml`: `href` должен совпадать с публичным URL маршрута. При новой группе согласуй `layout` в `settings.yaml`. Виджет добавляй при наличии подтверждённых параметров и секретов; проверяй формат по актуальной документации Homepage. Не переноси секреты в скил, ответы или Nix store.
5. Сделай минимальные точечные правки. Проверь YAML локальным парсером, по возможности отклоняющим повторяющиеся ключи. Проверь связи router → service → backend, уникальность нового hostname и согласованность URL карточки. Синтаксическая проверка не подтверждает доступность backend; если проверяешь HTTP, сообщи результат отдельно, не выводя секреты и содержимое ответов приложения.
6. Сообщи изменённые файлы, URL сервиса и результаты проверок. File provider настроен с `watch: true`, поэтому правка может примениться сразу. Не перезапускай контейнеры и не запускай системную активацию без запроса.

## Если задача затрагивает Nix

Используй скил `nix`. Для этого окружения репозиторий конфигурации — `~/new_config`: сначала прочитай его инструкции, проверь Git, найди модуль и целевой хост. Не считай наличие каталога приложения доказательством существования его Nix-декларации. Храни общие инструкции этого скила в репозитории, а рабочие секреты и данные — вне Nix store.
